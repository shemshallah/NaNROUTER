# Wave Service Facade

`runner_riddle/wave_service.py` adds a small authenticated Python facade over
`runner_riddle/wave_store.py` for the R8 BS0DB/MC0DB control plane.

The facade is transport-neutral: it is not an HTTP server, not a worker, and
not a mathematical kernel. It authenticates a caller role and delegates the
operation to the existing store. All persistence, idempotency, lease, and
append-only behavior remains owned by `WaveStore`.

## Boundaries

- **No host math.** The facade never computes wave transforms, residuals, or
  any other numerical result.
- **No secret persistence.** Submit, worker, and admin credentials are never
  passed to `WaveStore` and never written to BS0DB or MC0DB.
- **No plaintext credential retention.** The service keeps only SHA-256 digests
  of its configured tokens in process memory.
- **No HTTP listener.** A future transport layer should call this facade rather
  than reimplement its authorization rules.
- **No new database schema.** The facade uses the existing `wave_job`,
  `wave_lease`, `wave_capability`, `wave_trace`, `wave_seal`, and
  `wave_signature` records.

## Roles

| Role | Allowed operations |
|---|---|
| `submit` | `submit_job`, `store_trace`, `store_seal`, `store_signature` |
| `worker` | `lease_job`, `complete_job`, `fail_job` |
| `admin` | `register_capability`, `store_trace`, `store_seal`, `store_signature` |

Roles are not interchangeable. For example, an admin token cannot submit or
lease a job, and a submit token cannot complete one. Evidence writes are the
only operations shared by two roles (`submit` and `admin`).

## Construction

```python
from runner_riddle.wave_service import WaveService
from runner_riddle.wave_store import WaveStore

store = WaveStore("bs0db.sqlite3", "mc0db.sqlite3")
service = WaveService(
    store,
    submit_token=submit_token,
    worker_token=worker_token,
    admin_token=admin_token,
)
```

All three tokens are required. Each must:

- be a non-blank string;
- contain at least 16 characters (`MIN_TOKEN_LENGTH`);
- differ from the other two tokens.

Missing, weak, or reused tokens raise `WaveServiceConfigError`. Authentication
failures raise `WaveServiceAuthError`, which is both a `WaveServiceError` and a
`PermissionError`. Errors never echo the supplied or configured token.

Tokens should be generated by a random secret source and supplied from the
deployment secret manager or environment. The facade does not rotate, revoke,
or persist them.

## API

```python
service.submit_job(
    token, job_id, universe_id, operator_digest, generation, payload, now_tick,
    *, kind="wave", operator_id=None, precision=None, workspace=0,
)

service.lease_job(
    token, owner, now_tick, lease_ticks=64,
    *, expected_generation=None, max_attempts=8, job_id=None,
)

service.complete_job(
    token, job_id, lease_token, lease_epoch, result_digest, now_tick,
    *, result_generation=None, lease_owner=None,
)

service.fail_job(
    token, job_id, lease_token, lease_epoch, now_tick, error,
    *, lease_owner=None,
)

service.register_capability(
    token, kernel_id, runner_id, verified_digest, workspace, precision,
    *, status="declared", epoch=1, nanclock_tick=0,
)

service.store_trace(
    token, universe_id, generation, digest, producer, nanclock_tick, signature,
    *, payload=None, payload_blob=None, trace_id=None, job_id=None,
)

service.store_seal(
    token, universe_id, generation, digest, producer, nanclock_tick, signature,
    *, payload=None, payload_blob=None, seal_id=None, job_id=None,
)

service.store_signature(
    token, universe_id, generation, kind, digest, producer, nanclock_tick,
    signature, *, payload=None, payload_blob=None, signature_id=None,
)
```

`append_trace`, `append_seal`, and `append_signature` are aliases for the three
evidence methods, matching the `WaveStore` names.

`health()` takes no token and returns the `WaveStore.health()` report directly:
schema version, BS0DB/MC0DB status, job and lease counts, and the number of
native-verified capabilities. It contains no credential material.

## Example

```python
job = service.submit_job(
    submit_token, "job-42", "universe-0", operator_digest, 7,
    {"step": 1}, now_tick=100, precision="Q16.16", workspace=4096,
)

lease = service.lease_job(worker_token, "MC0:0/R0", now_tick=110,
                          lease_ticks=32, expected_generation=7)

done = service.complete_job(
    worker_token, "job-42", lease["lease_token"], lease["lease_epoch"],
    result_digest, now_tick=120, lease_owner="MC0:0/R0",
)
```

The caller still owns scheduling, transport, request-size limits, rate limits,
and the decision to retry or expire work. The facade only enforces the role
boundary before invoking the store's existing state machine.

## Security notes

- Authorization comparisons use `hmac.compare_digest` over fixed-size SHA-256
  digests. Every configured role is compared on every check.
- The service object's `repr` omits credentials.
- `health()` contains no credentials.
- Service tokens are not part of any SQL statement or row payload. Lease tokens
  remain opaque store-generated values used by `complete_job`/`fail_job`; they
  are not service credentials.
- `WaveServiceConfigError` and `WaveServiceAuthError` messages identify the
  role or operation, never the token value.

## Limitations

- No HTTP/node transport, request parsing, rate limiting, or TLS. This is a
  Python call boundary only.
- No token rotation, revocation, expiry, or per-universe ACL; all holders of a
  role token share that role.
- No audit log of authorization decisions.
- No transaction spanning multiple store calls. Each facade method delegates a
  single store operation.
- No operator registration, feedback, match-index, or lease-expiry facade
  methods yet; use `WaveStore` directly for those operations.
- Service tokens live in process memory (as digests) for the lifetime of the
  `WaveService` instance.

## Tests

```sh
python3 -m unittest tests.test_wave_service -v
```

The suite covers constructor token policy, role rejection, the submit/lease/
complete and fail paths, admin-only capability registration, evidence role
rules, token-free health, constant-time comparison use, and a byte scan proving
plaintext service tokens are not written to the SQLite files.
